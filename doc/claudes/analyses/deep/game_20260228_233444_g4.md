**Players**: o3 Vorthos (openai/o3) vs GLM47 Timmy (z-ai/glm-4.7)
**Format**: Standard (Jumpstart Limited)
**Result**: GLM47 Timmy won on turn 17
**Config**: round-robin

## Findings

- Filed P2 bug: `chosen` field in decisions export is wrong when bridge uses `id` instead of `index` (causes false blunder annotations). See `issues/chosen-field-wrong-when-id-overrides-index.json`.
- Annotation 13 is a false positive: claims o3 targeted itself with Gnawing Zombie drain, but bridge log and game events prove GLM47 Timmy was actually targeted. Root cause is the bug above.
- No code bugs in bridge/MCP/puppeteer — all 7 failed tool calls and all timeouts are model behavior.

## Notes

- o3 failed to execute Tree of Perdition + Triskaidekaphobia combo **3 separate times**, each time activating Tree to move the opponent OFF 13 life. o3 recognized the combo in reasoning but consistently failed to execute it, either from life total tracking errors or compulsive Tree activation.
- GLM47 (glm-4.7) had 12 mana plan cancellations from referencing tapped/stale land IDs, wasting ~5 full turns.
- GLM47 had 2 empty LLM responses, both handled by retry logic.
- o3 sends `index=0` as default with every choose_action call (25 out-of-range diagnostics). Bridge handles this correctly but it causes the `chosen` field bug above.
- o3 cost $2.83 vs GLM47 $0.64, yet o3 played worse strategically. The game demonstrates that expensive reasoning models can still fail badly at multi-step combo execution.
