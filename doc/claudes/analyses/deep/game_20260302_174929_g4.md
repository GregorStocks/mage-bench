## Findings

- **P2 bug filed**: `get-action-choices-undeclared-has-playable-cards` — `has_playable_cards` key not declared in GetActionChoicesTool, causing MCP validation error. Hit GptOSS 3 times on consecutive critical turns, blinding it to available actions. BridgeCallbackHandler.java:3357.
- **P3 bug filed**: `superstitious-personality-thriving-isle-color` — Superstitious personality caused Grok4F to pick Red for Thriving Isle in mono-blue deck. Chat confirms "lucky red glow" reasoning.
- **Model issue (not filed)**: gpt-oss-120b hallucinated game state badly on turn 2 — believed it played 2 lands and cast 2 creatures when it only played 1 Plains. Never recovered. 4 empty LLM responses, 5 invalid_choice errors from stale object IDs. This model may need evaluation for basic action execution reliability.
- **Existing issue confirmed**: `get-action-choices-undeclared-action-taken` is a sibling bug in the same tool (different key). Both should be fixed together.

## Notes

- gpt-oss-120b (openai/gpt-oss-120b) appears to batch plan actions in a single LLM response based on predicted game state rather than reading actual choices. When any action fails, the cascade breaks the whole plan. This is a model architecture issue, not a code bug.
- The superstitious personality is borderline — heavy chat spam (15 messages, all themed) but only one actual gameplay decision infected. The Thriving Isle color choice is the clearest evidence of personality infection in a "harmless" personality we've seen.
- The `has_playable_cards` bug is arguably P1 in severity since it completely prevents a player from seeing actions on affected turns, but since it only triggers in the specific `actionsPassed > 0 && hasPlayableCards` code path, P2 seems right.
