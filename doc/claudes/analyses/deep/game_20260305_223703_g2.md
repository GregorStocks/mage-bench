# game_20260305_223703_g2

**Players**: GPT54 Critic (openai/gpt-5.4, Basri+Snow) vs G31FL Sarge (google/gemini-3.1-flash-lite-preview, Cycling+Experimental)
**Format**: Limited (Jumpstart)
**Result**: GPT54 Critic won on turn 11 (22 life vs 0)
**Config**: round-robin-jumpstart

## Findings

- **P1 filed: batch-attack-declared-schema-mismatch** — `ChooseActionTool.Result.declared` is `List<Object>` which generates `items.type = "object"` in output schema. Batch attacks return strings, causing OpenAI to reject every batch attack result. 5 failures in this game. Root cause in `McpToolRegistry.getListItemType()`.
- **P3 filed: gemini-flash-lite-skips-combat-never-attacks** — Flash Lite used `pass_priority(until="my_turn")` to skip combat entirely, never attacked, hallucinated blocker IDs, kept 1-land hand. Model quality issue.
- GPT-5.4 (critic personality): personality stays in chat only, reasoning remains game-analytical. No personality infection in decisions.
- Sarge (drill-sergeant personality): fully in-character chat, but reasoning encrypted (Gemini format) so can't assess infection.
- No errors in errors.log, no out-of-range diagnostics, no index-out-of-range errors.

## Notes

- The batch attack schema bug is high-impact: it affects every combat phase for every game using OpenAI models with structured output validation. The attacks still execute server-side but the model gets an error response, wasting ~10 LLM calls per game on recovery.
- Flash Lite's `until="my_turn"` pattern completely bypasses combat phases — the model never even sees a `declare_attackers` prompt. This could be addressed by restricting the `until` parameter values in weaker model toolsets.
- Empty error message when batch block fails (pilot log line 119: "Action failed: ") — the error details are in `result.failed` but `result.error` is null. Minor UX issue, not filed separately.
