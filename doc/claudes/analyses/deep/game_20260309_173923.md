**Players**: Opus Brewer (anthropic/claude-opus-4.6) vs Gem3P Coach (google/gemini-3-pro-preview)
**Format**: Limited
**Result**: Opus Brewer won on turn 17
**Config**: seed1-vs-seed3

## Findings

- Turn-8 combat damage reproduced the already-known `GAME_GET_MULTI_AMOUNT` failure mode from the raw logs: Opus saw a trample assignment with one listed item (`Celestial Enforcer`, `total_min=3`, `total_max=9`) and retried `amounts=[3,6]` / `[6,3]` for ~44 seconds because the prompt gave no valid overflow target. I did not file a new issue because `origin/master` already fixed this exact bridge bug in commit `25ab6dbde1` (`Reject malformed GAME_GET_MULTI_AMOUNT arrays`), and the resolved issue file was deleted in that commit.
- Gem3P Coach hit the recurring Gemini provider/harness adjacency `BadRequestError 400` twice (`Please ensure that function response turn comes immediately after a function call turn.`). No new issue filed; this matches the already-documented `gemini-function-response-adjacency` issue from commit `e5c61d3719`.
- Most of Gem3P Coach's loss was gameplay quality, not platform failure: the export annotations line up with the raw logs on missed `Revitalize` windows, free attacks declined, and several missed `Angelic Ascension` opportunities before Ivy Lane Denizen snowballed.
- Filed P4 issue [`game-timeline-turn-filter-breaks-on-v7-exports.json`](/home/gregor/code/worktrees/russet-egret-rattan/issues/game-timeline-turn-filter-breaks-on-v7-exports.json). While analyzing this game, `scripts/analysis/game_timeline.py --turns 7-9` returned zero events because the script assumes `snapshots[].ts` exists, but this v7 export omits snapshot timestamps and the filter maps every `llmEvent` to turn 17.

## Notes

- For this export, `game_events.jsonl` only had `game_action`, `player_chat`, and `game_over`, so the bridge logs plus `llmEvents` were the most reliable way to reconstruct the turn-8 multi-amount loop.
- Do not trust `game_timeline.py --turns` on v7 exports until the script is fixed; check whether `snapshots[0]` has a `ts` field first.
