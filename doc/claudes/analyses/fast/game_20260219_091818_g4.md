# game_20260219_091818_g4

**Players**: Grok4F Gramps (grok-4-fast) vs GLM47 Coach (glm-4.7)
**Format**: Constructed - Modern (Two Player Duel)
**Result**: GLM47 Coach won on turn 11
**Config**: round-robin batch (091818)

## Findings

- 19 failed tool calls — the most error-prone game in this batch. Both models repeatedly used stale IDs. Grok had 8 `llm_error` events and a context_reset.
- Grok tried `choose_action` with `text: "GLM47 Coach"` (twice) — trying to pass a player name as a choice. Clear model confusion about the API.
- Grok had a `no_pending_action` error (10s timeout) — the game state moved on while the model was thinking.
- GLM had `GAME_CHOOSE_ABILITY requires index=N` errors when trying to use `answer: false` — wrong parameter type for ability selection.
- GLM had `get_oracle_text` failure with stale `p48`.
- Zero critical errors.
- Rich game: Grok played 5-color Omnath with fetches, Teferi/Wrenn and Six/Phlage/Leyline Binding/Solitude. GLM played Eldrazi ramp with Ugin's Labyrinth, Sowing Mycospawn, Sire of Seven Deaths.
- GLM's Kozilek's Return (triggered by Sire of Seven Deaths cast) wiped Grok's board twice in one turn, then Sire's 7/7 menace/lifelink closed it out.
- Grok's chat was an entertaining "old timer" character consistently throughout. GLM played a "coach" character.

## Notes

- High error rate from both models suggests the API interface is particularly confusing for non-Anthropic models in complex board states.
- Grok's `text` parameter misuse and stale ID persistence suggest models don't fully understand when IDs become invalid.
- GLM47's play was actually strong despite errors — correctly sequencing Kozilek's Return with big Eldrazi casts.
