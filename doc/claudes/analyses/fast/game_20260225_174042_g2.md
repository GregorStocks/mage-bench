## Error Patterns

- **73 total failed tool calls** across all players:
  - Gem25P Tactic: 31 errors (8 invalid_choice, 8 missing_param, 8 index_out_of_range, 1 no_pending_action, 6 string errors)
  - Llama4 Analyst: 15 errors (4 invalid_choice, 4 missing_param, 3 index_out_of_range)
  - Opus Hothead: 14 errors (13 invalid_choice, 1 string error)
  - Gem25F Diplom: 13 errors (9 invalid_choice, 2 missing_param, 2 string errors)
- **Stale object ID pattern**: All players repeatedly tried to use object IDs (p44, p80, p95, p164, p198, etc.) that were no longer valid. This is the dominant error — models cache IDs from previous get_action_choices calls and reuse them after game state changes.
- **Attack-out-of-phase**: Gem25P Tactic and Llama4 Analyst both tried to pass `attackers` parameter when not in declare_attackers phase (7+ occurrences). Models don't track combat phases well.
- **Mana plan failures**: Opus and Gem25P had multiple "Spell cancelled — mana plan was incorrect" errors.
- **"Unknown short ID: Opus Hothead"**: Gem25F Diplom passed a player name where an object ID was expected — likely a get_oracle_text call.

## Notes

- No new bugs found — the error patterns (stale IDs, attack-out-of-phase, mana plan failures) are all known model behavior issues, not platform bugs.
- The stale ID problem is pervasive across all models and accounts for most errors. A potential improvement would be to include a hint in error messages telling models to call get_action_choices again.
- Opus cost 136x more than Gem25F Flash for the same game. Cost efficiency is a major consideration.
